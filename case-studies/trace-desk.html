Trace Desk: USDT Investigations

A crypto investigation workspace that pulls real Ethereum USDT transfers, decodes them from raw logs, maps a bounded wallet network and hands a checksummed case file to QC.

Who it is for

Crypto investigators and blockchain intelligence teams who need evidence a reviewer can verify.

What I built

A node collector, a log decoder with exact integer amounts, an evidence verifier, a bounded graph, live browser queries, portable case files and QC rounds.

Result

The saved case rebuilds identically offline from raw node responses, and every number traces back to a transaction.

The problem

Investigating a crypto address usually means copying transactions out of block explorers into spreadsheets. Evidence gets lost, amounts get rounded, and the reviewer cannot tell what was checked.

I built this twice. Version 1 (USDT Investigator) proved the evidence pipeline on one saved case. Version 2 (Trace Desk) added live queries, case files and a QC workflow.

Architecture

How data moves from source to decision.

  1. CollectJSON-RPC calls for USDT Transfer logs and block headers from a public node, in batches.
  2. VerifyRaw responses saved with SHA-256 checksums and block hashes in a manifest.
  3. DecodeSender, recipient and amount from raw log data, kept as whole-number base units.
  4. Bound the graphStart from a wallet with 6 to 12 counterparties and expand at most two hops.
  5. InvestigateWarning signs that link to the transfers behind them; pin evidence.
  6. Hand offJSON case file with a checksum; frozen QC snapshots for review.

Technologies

  • Python 3 (standard library)
  • Ethereum JSON-RPC
  • JavaScript ES modules
  • SHA-256 checksums
  • unittest and node:test

Engineering decisions

Hard limits on scope

700 blocks, 1,000 transfers, five wallets and a two-hour window per live query. An over-budget query never replaces the case on screen.

Never use floating point for money

Amounts stay as integer base units from decoding to export.

Warning signs, not risk scores

Matching amounts in sequence are shown as a lead with the transfers behind it, not as proof of the same funds.

Empty means empty

A window with no transfers is reported as no data, never as a clean wallet.

Frozen QC rounds

If the analyst edits evidence after submission, the earlier review no longer applies.

Tests

49 tests (41 in Trace Desk, 8 in version 1), run with one command and no network.

  • JavaScript decoding agrees with the Python saved evidence
  • Large uint256 amounts stay exact; removed logs and malformed hashes fail closed
  • No activity is not a clean bill of health, and a provider failure is not an empty case
  • Checksums detect changed payloads; fabricated QC outcomes are rejected on import
  • Resubmission keeps the previous outcome and creates a fresh snapshot

Results

  • 80 blocks (25,929,879 to 25,929,958) and 7,640 USDT transfers decoded
  • A 15-wallet, 15-transfer case with a written report
  • Live queries run from the browser against a public node with no server and no keys

Limitations

  • A wallet address is not a person; nothing is attributed
  • A window is a slice of activity, not full history or balance
  • Data comes from one public node; checksums catch local changes, not node errors
  • Notes stay in the browser until a case file is saved

What I would build next

  • Cross-checking a second node for the saved case
  • Tron support using the same evidence model
  • Signed case files so a reviewer can verify who produced them
