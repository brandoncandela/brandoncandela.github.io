Sanctions Review Desk

Takes a possible OFAC name match to a documented decision a QC reviewer can check, with live search over the official list refreshed every hour.

Who it is for

Sanctions screening analysts, trade compliance teams and QC reviewers.

What I built

A scheduled OFAC data pipeline, in-browser name search, identifier comparison, evidence pinning, information requests and multi-round QC.

Result

A screening hit becomes a reviewable case file, and the search never answers from data older than a day.

The problem

A screening tool says a customer or shipment party might match the sanctions list. The analyst still has to compare identifiers, request what is missing, decide and explain it well enough that QC can challenge it.

Architecture

How data moves from source to decision.

  1. RefreshA GitHub Action downloads the official SDN and alias files every hour.
  2. PublishThe normalized list is committed as JSON with a retrieval timestamp.
  3. SearchThe browser loads it and matches every query word against names and aliases, ignoring accents and punctuation.
  4. CompareEach identifier marked as supporting, against or unknown.
  5. DocumentPinned sources, information requests and a written assessment.
  6. QCFrozen submissions, findings, returns and resubmissions in one case file.

Engineering decisions

Refuse stale data

If the list copy is more than 24 hours old the search will not run, because a confident answer on old data is worse than no answer.

Unknown is its own state

Missing information is never counted as a mismatch.

Keep sanctions and export controls apart

A shipment can raise both, and the case records them separately.

Validate case files on import

Broken references are rejected so a reopened case is the case that was saved.

Tests

21 node:test cases, run with one command and no network.

  • Official OFAC CSV parsing keeps quoted commas and the end-of-file marker
  • A fresh feed is accepted; a stale or failed feed is rejected
  • Editing a draft cannot change a submitted case
  • A QC return needs an analyst response before resubmission
  • Malformed, dangling or colliding case files are rejected on import

Results

  • Three training cases covering rerouted shipments, a similar name and a third-party payer
  • Live search over the current SDN list with the retrieval time on every result

Limitations

  • Searches SDN names and aliases only; no 50 Percent Rule ownership, other lists or export classifications
  • Reviewer names are typed in, not authenticated
  • Case files can be edited by anyone who holds them

What I would build next

  • Ownership checks for entities owned 50% or more by listed persons
  • Consolidated Screening List coverage
  • Authenticated reviewers and a locked audit trail
